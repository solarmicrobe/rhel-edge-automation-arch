# ADR 0001: Modern RFE Architecture Direction

## Status

Accepted for the `custom` branch.

## Context

This repository started as a reference architecture for deploying and operating RHEL for Edge automation on OpenShift. The current implementation mixes several concerns:

- Installing or configuring an ArgoCD control plane.
- Rendering ArgoCD `Application` and `AppProject` resources.
- Deploying cluster components such as OpenShift Virtualization, Pipelines, Nexus, Quay, and ODF.
- Running RFE artifact workflows.
- Publishing produced artifacts.

That model fits a reference empty-cluster deployment, but it does not fit every real cluster. In the target cluster for this fork, a cluster ArgoCD already exists, and RFE automation should not implicitly become the cluster-wide GitOps control plane.

The current charts also carry older assumptions:

- The ArgoCD chart grants broad cluster-level privileges.
- BYO component behavior is mostly modeled as `disabled: true`, which is too coarse.
- Some workflows assume repo-managed infrastructure even when a component is brought by the platform.
- The image-builder VM path historically pulled and stored a custom base image even though OpenShift Virtualization provides common OS `DataSource` objects.
- Some build paths use OpenShift `BuildConfig`; those paths should be re-evaluated before migration to Tekton Pipelines.

Existing custom changes in this fork are evidence of operational problems, not design authority. Their intent can be preserved, but implementation should be rewritten where the modern architecture makes older workarounds obsolete.

## Decision

The `custom` branch will target a modern RFE architecture with a BYO-first operating model.

The primary purpose of this repository is to produce RHEL for Edge artifacts. It should not implicitly own the cluster GitOps control plane or unrelated platform services.

### Deployment Mode

The top-level deployment mode must be explicit. Mode selection should establish defaults, but templates should branch primarily on explicit lower-level values.

Planned modes:

- `byo-cluster-argocd`: target an existing cluster ArgoCD.
- `byo-rfe-argocd`: target an existing RFE-specific ArgoCD.
- `managed-rfe-argocd`: install and target an RFE-specific ArgoCD.
- `reference-full-stack`: retain a broader reference deployment profile.

### ArgoCD Targeting

ArgoCD installation ownership and ArgoCD application targeting are separate concerns.

RFE `Application` resources should target an abstract ArgoCD control plane, configured by values such as:

```yaml
argocd:
  target:
    namespace: openshift-gitops
    project: rfe
    server: https://kubernetes.default.svc
  install:
    enabled: false
  appProject:
    create: false
    name: rfe
```

The target ArgoCD may be:

- an existing cluster ArgoCD,
- an existing RFE-specific ArgoCD,
- or an RFE-specific ArgoCD installed by this repository.

### AppProject and Access

`AppProject` management belongs to the ArgoCD control-plane integration layer, not the normal workload layer.

The modern default should be restrictive:

- allow configured source repositories, not all repositories;
- allow explicit destination namespaces;
- deny cluster-scoped resources by default;
- enable cluster-scoped resources only through named capabilities.

Kubernetes RBAC grants for ArgoCD access should also be explicit. Access manifests may be generated by this repository, but they should live in a separate access layer that can be applied deliberately by a cluster admin or platform process.

### Component Lifecycle

Cluster components should use lifecycle modes instead of overloaded `disabled` flags:

```yaml
components:
  quay:
    mode: managed # managed | byo | disabled
    namespace: quay
    connection:
      registry: quay.apps.example.com
      organization: rfe
      repository: edge
```

Mode semantics:

- `managed`: this repository owns installation, namespace creation where needed, generated routes, and downstream wiring.
- `byo`: this repository does not install or mutate the component; required connection details must be provided.
- `disabled`: this repository neither installs nor references the component.

BYO must not secretly install or mutate the component. It may only render clearly named integration resources when explicitly enabled.

### Workflow Defaults

RFE artifact workflows are enabled by default inside an explicit deployment mode because producing RFE artifacts is the purpose of this repository.

Components describe available infrastructure. Workflows describe intent.

Example workflow model:

```yaml
workflows:
  imageBuilderVM:
    enabled: true
  composeImage:
    enabled: true
  publishOstree:
    enabled: true
  publishIso:
    enabled: true
  serveKickstarts:
    enabled: true
```

Every enabled workflow must either own its dependencies or receive complete BYO connection details. Missing required details should fail at Helm render time with a clear message.

### Image Builder Base Image

The modern path is OpenShift Virtualization `DataSource` only.

The `custom` branch should not preserve the PVC/Nexus base-image staging path as a first-class option. Nexus may still be used for produced artifacts, but it should not be required to boot the image-builder VM.

### BuildConfig Modernization

BuildConfig modernization should begin with workflow inventory, not direct translation.

Do not migrate a `BuildConfig` unless the repository still needs that build after the DataSource-only architecture is defined. Some build paths may disappear instead of becoming Tekton Tasks or Pipelines.

## Consequences

This direction should make BYO behavior explicit and reduce accidental cluster ownership. It will also require changes across docs, values, helper templates, chart validation, ArgoCD resources, and workflow charts.

The reference full-stack path can remain, but it should become visibly broader than the modern defaults.

## Follow-up Work

- Document the current chart and workflow inventory.
- Define the new values API for deployment modes, ArgoCD targeting, components, connections, workflows, and access capabilities.
- Add Helm render-time validation for invalid mode and dependency combinations.
- Refactor ArgoCD install, AppProject, and access grants into separate concerns.
- Remove the PVC/Nexus base-image staging path from the modern image-builder flow.
- Inventory `BuildConfig` usage and retire or migrate each path based on the modern workflow model.
